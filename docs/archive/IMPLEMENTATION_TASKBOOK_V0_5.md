# v0.5 Engineering Validation 实施任务书

## 1. 任务与交付目标

你负责修改当前 Windows C# WinForms 启动器，使其成为可验证、可诊断的网络与时区启动辅助工具。本任务书结合《ChatGPT 启动器下一阶段修改方案》及当前源码审查结果制定。

以实际源码为准。README.md、PROJECT_MEMORY.md 和 PROJECT_SUMMARY_FOR_AUDIT.txt 中的历史技术断言不是已验证事实，也不是必须保留的要求。

交付目标：修复明确安全及可靠性缺陷；验证目标客户端对环境配置的实际采用情况；根据证据选择启动方式；完成必要的职责拆分。允许验证结论为“不支持”或“尚未验证”，禁止用探测程序成功代替真实客户端成功。

## 2. 工作约束

- 先读取适用的 AGENTS.md，检查工作区改动，保留用户已有工作。
- 禁止批量删除文件或目录；只允许一次删除一个明确路径的文件。不要使用递归删除命令。若确需批量清理，交由用户手动操作。
- 本任务书授权源码、文档和本地测试产物的修改，不授权发布、上传数据或更改系统代理、系统时区、证书信任配置。
- 不得在测试中关闭用户正在使用的 ChatGPT/Codex。涉及真实客户端退出、重启或用户级环境修改的集成测试，应先说明影响并取得明确授权；此前继续完成所有不依赖这些操作的工作。
- 不执行现有 build.bat 进行初始验证：它编译后自动启动程序。先采用仅编译命令或新增仅构建入口。
- 不引入第三方代理服务、自动更新、节点测速、主题和动画。不为测试引入生产运行时依赖。
- 维持轻量部署；若调整最低 .NET Framework 版本，明确记录编译目标、运行要求和兼容性变化。
- 未明确要求并行 agent 工作时，按顺序实施，不自行创建其他任务或子 agent。

## 3. 开始前建立基线

1. 阅读 Program.cs、LauncherCore.cs、UIControls.cs、build.bat 及现有说明。
2. 记录当前源码能否编译、编译器及目标框架；新产物使用独立明确路径，避免覆盖正在运行或尚未核对的旧程序。
3. 创建 VALIDATION_REPORT_V0_5.md，记录测试环境、客户端版本与身份、启动路径、执行步骤、预期、实际和证据位置。
4. 状态使用“通过／失败／未验证／不适用”，不得将未执行的项目写成通过。

## 4. 第一阶段：修复明确缺陷【P0】

### 4.1 TLS 与网络错误

- 删除无条件返回 true 的证书验证回调，恢复正常证书校验。
- 移除明文 HTTP GeoIP 回退；只保留经过验证可用的 HTTPS 接口。
- 根据实际目标框架选择系统默认安全协议；旧框架需要明确兼容方案，不得简单删除设置后退回旧协议默认值。必要时明确提高最低框架要求。
- 区分证书错误、代理不可达、超时、HTTP 错误、响应解析错误；失败不得转成成功或静默绕过验证。
- 验收：有效证书请求可正常处理；无效证书被拒绝；失败原因可见；不存在放行任意证书和明文回退代码。

### 4.2 产品文案与成功状态

- 删除“防封号”“100%安全”“安全无风险”“全局零污染”等承诺，同步界面、README 和审计说明。
- 使用“ChatGPT Windows 网络环境启动器”作为展示名称；内部命名和旧配置目录可暂保留，避免不必要迁移。记录保留原因。
- 时区比对仅描述配置与探测结果是否一致，不推断账号风险。
- 将“启动请求成功”“目标进程已启动”“配置实际生效”分开表达；没有证据时不得显示后者。

## 5. 第二阶段：核心机制验证【P0，决定后续架构】

先完成最小验证，再决定是否保留用户环境广播路径。

### 5.1 必须区分的证据层级

1. 启动器构造了什么环境值。
2. 新建测试子进程实际收到了什么环境值。
3. 如采用 Electron Probe，其主进程、渲染进程的 Date、Intl 时区和各自网络请求实际表现如何。
4. 当前版本真实客户端在相应启动路径下的实际表现。

Probe 版本应记录；它只能证明被测试运行时的行为。不要为获得预期结果在 Probe 内主动调用 setProxy 等配置 API，然后声称环境变量自动生效。

### 5.2 验证项目

- TZ：选择两个差异明显的有效 IANA 时区，记录 Intl 返回值、当前时间偏移；对 UTC 字符串模式单独验证解析和符号语义。
- 代理：记录 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY 的传递与采用情况；区分 HTTP 代理与 SOCKS，不能因 TCP 端口可连接就认定协议正确。
- 出口：启动器 GeoIP 结果只代表该次探测请求。真实客户端请求需通过可归属到目标进程的代理日志或其他可靠证据核对；分流时不能推断所有目标域名出口一致。
- Store：单独验证 COM 激活是否创建新实例、目标实例是否获得环境；激活返回成功不能证明注入生效。
- 直连：验证子进程环境中相关代理变量已被移除，但不要声称可绕过系统代理或 TUN。
- 无法合法、可靠观察真实客户端行为时，写明缺失证据和复现步骤，标记“未验证”。不要求修改客户端安装文件或绕过安全机制。

### 5.3 架构决策与门槛

- 独立版优先使用 UseShellExecute=false 与独立子进程环境，禁止无必要地修改用户级环境变量。
- Store 广播注入只有在当前目标版本获得直接证据后才可标记为已验证；失败或未验证时，不得作为保证生效的默认能力，可提供明确标注的普通启动路径。
- TZ、代理分别评估；某一项失败不意味着另一项自动失败或成功。
- 在报告中记录保留、替换或禁用每条启动路径的理由。不得为了完成原计划继续加固已经证实无效的路径。

## 6. 第三阶段：可靠性修复【P1】

### 6.1 环境事务（仅用于确有必要保留的用户环境路径）

- 修改前保存每个变量原始状态，区分不存在与存在；先可靠落盘恢复记录，再开始修改。
- 记录版本、事务 ID、目标作用域、原值和拟写入值；不要把变量值无必要地写入诊断日志，尤其是含认证信息的代理地址。
- 构造或初始化部分失败时也必须回滚；不要只依赖成功构造对象后的 Dispose。
- 正常及下次启动恢复采用 Compare-and-Restore；当前值不等于临时值时不覆盖，记录冲突。
- 单项恢复失败不得阻断其他项；未恢复项保留记录，只有所有项成功恢复或明确解决后，才单文件删除记录。
- 在恢复及事务前取得覆盖同一用户环境写入的单实例锁；考虑同一用户不同会话，并说明此锁不能阻止外部程序修改环境。
- 明确剩余限制：异常后到恢复前仍有影响窗口；其他程序可能已继承临时环境；比较与写入不是跨程序原子事务；不能宣称完全隔离。
- 使用模拟环境存储测试部分写入失败、恢复失败、外部修改、重复恢复和日志损坏。不要通过强杀真实客户端测试恢复。

### 6.2 启动、退出与界面响应

- 定位目标安装并确认身份后，再决定是否退出已有实例；不要按 ChatGPT/Codex 名称一并关闭。
- 结合可执行路径、包身份核对目标；身份无法确认时不强制结束。
- 优雅关闭和强制结束分开；保留强退确认，强退后等待并验证退出，失败时不继续宣称新环境生效。
- 给 PowerShell 输出读取和进程等待设置有效的整体超时；阻塞 ReadToEnd 后再 WaitForExit 不算实现超时。
- 将阻塞启动准备工作移出 UI 线程；禁用重复启动入口，避免 Application.DoEvents 引入重入。
- 正常与降级路径均显式移除应清除的代理变量，不得从启动器原环境继承回来。

### 6.3 探测与时区

- 探测、端口检查、预览和启动统一使用同一个经过校验的代理配置，包括主机、端口、协议。
- 代理配置或网络模式变化后使旧探测结果失效；忽略已过期异步请求的返回值。
- 时区偏移使用分钟或 TimeSpan，支持 30/45 分钟偏移；缺失偏移显示未知，不得当作零。
- IANA 时区与固定 UTC 偏移分开表达，城市快捷配置优先 IANA；不要把固定冬令时偏移当作全年值。
- 验证 IANA 输入与 UTC 模式运行时支持情况；不能支持的格式应禁用或明确报错。

### 6.4 配置

- 使用与目标框架兼容的标准 JSON 序列化替代 Regex，覆盖转义字符和损坏数据。
- 配置保存应避免截断旧文件；失败返回可诊断错误，界面不得提示保存成功。
- 保留既有配置迁移能力；新增“TZ 关闭”等设置时，定义其语义、默认值和旧配置兼容行为。

## 7. 第四阶段：必要重构【P2】

逐步抽取 LauncherService、EnvironmentManager、NetworkProbeService、ProxyService、ChatGPTLocator、SettingsStore，使 UI 只承担输入与展示。可以合并合理的小模块，不以文件数量作为验收标准。

拆分应服务于前述修复与可测试性，不进行无关重写。DPI 优先修复实际遮挡和不可操作问题，主题美化继续暂缓。

## 8. 测试范围与交付验收

第一轮先覆盖当前可用机器的真实客户端版本及存在的安装方式。完整矩阵包含 Store/独立版、HTTP Proxy/TUN/Direct、TZ 开/关、Windows 10/11、x64/ARM64；没有设备或安装包的组合标记未验证，不宣称全平台兼容。

最低验收要求：

- 仅构建命令成功，不自动启动客户端；记录命令与结果。
- 安全缺陷和误导文案已修复。
- 子进程环境传递、代理变量清除、配置读写、时区边界和保留的事务机制有针对性验证。
- 真实客户端结果有可复现证据，或明确标注未验证并限制对应产品承诺。
- 启动、探测及保存失败不显示成功；不会按名称误关其他应用。
- UI 基本操作可用；未授权集成测试保持未执行状态，不伪造验收。

交付以下内容：

1. 修改后的源码与仅构建入口。
2. VALIDATION_REPORT_V0_5.md：结果、证据、环境、未验证项和剩余限制。
3. 更新后的 README：真实功能、支持范围、最低运行要求和构建步骤。
4. 最终回复：概述修改、已执行检查、失败或未验证项，以及需要用户配合的具体测试。若核心机制被证实无效，直说，并说明对应能力如何处理。

除确需用户授权或缺少真实测试条件的步骤外，持续完成其余工作，不因单个阻塞项中止全部实施。不得把“编译成功”当成 v0.5 全部验收通过。
