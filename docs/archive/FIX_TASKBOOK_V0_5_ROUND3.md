## A. 构造异常必须释放已取得的锁【P1】

位置：EnvironmentTransaction.cs，UserEnvironmentTransaction 构造函数及 ReleaseLock。

复现：取得锁后，让 IEnvironmentStorage.GetVariable 在读取原始值时抛出 UnauthorizedAccessException；构造失败后锁仍被持有。当前代码只在部分显式 catch 中释放资源。

要求：

1. 将取得锁后的整个初始化阶段纳入统一异常清理结构，覆盖旧日志检查、环境读取、序列化、日志写入和环境注入。
2. 仅在构造完整成功后把锁生命周期移交给对象；任何构造失败均释放锁与句柄。
3. 正确区分尚未修改环境、已部分修改且回滚成功、回滚未完成；释放锁不能替代恢复或日志保留。
4. 保留原始失败原因和恢复状态，不因清理异常丢失主要错误。

验收测试：原始值读取失败、日志 Exists/Read 抛异常、首次日志写入失败、部分环境写入失败，均验证资源释放；已产生修改的场景同时验证回滚或未恢复日志保留。

## B. 恢复失败必须传到启动结果与界面【P1】

位置：EnvironmentTransaction.cs 的 Dispose/恢复逻辑；LauncherService.cs 的 Store 启动分支；Program.cs 的启动恢复与状态显示。

复现：先成功注入模拟 TZ，再让恢复写入失败。Dispose 正常返回，模拟环境仍为临时值，日志仍存在。LauncherService 先构造成功结果，在 finally 中吞掉 Dispose 异常，最终仍会报告成功。

要求：

1. 设计明确的事务完成结果，至少区分：已恢复、外部改值冲突、部分恢复失败、日志清理失败。可用显式 Complete/Restore 方法和结果对象；Dispose 负责兜底及资源释放，不得使调用方无法获知失败。
2. LauncherService 必须在恢复结果确定后组合返回值。客户端已经启动但环境恢复失败时，准确显示这两个事实，禁止普通绿色成功提示，也不要谎称客户端未启动。
3. 事务初始化错误不能一律写成“环境变量未被修改”：部分写入后回滚失败时该表述不成立。
4. Program.cs 必须处理 CheckAndRecoverDanglingTransactions 返回值。损坏日志、恢复失败及冲突需要可见提示，不能丢弃结果。
5. 恢复失败继续尝试其他项，保存未恢复记录；日志写入或删除失败也要反馈。不得因通知失败而阻断锁释放。
6. 外部改值冲突不覆盖；记录和显示冲突数量。避免把可能含代理凭据的原值/临时值直接写入普通诊断文案。
7. 不增加静默降级路径来绕开事务错误。

验收测试：恢复写入失败、恢复日志更新失败、日志删除失败、外部改值冲突、COM 成功但恢复失败、COM 失败且恢复失败。用可替换的激活器或等价纯逻辑验证启动结果组合，禁止真实 COM 启动测试。断言界面所用结果确实包含恢复状态，不能只检查日志存在。

## C. 恢复日志只允许管理约定变量【P1】

位置：EnvironmentTransaction.cs 的日志校验与 RecoverDanglingTransactionsLocked。

复现：构造版本正确、包含 Key=PATH 的模拟日志；当前恢复逻辑会修改模拟 PATH。当前校验只要求变量名非空。

要求：

1. 设置唯一、大小写不敏感的允许列表：TZ、HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY。新增变量必须显式扩展列表并补测试。
2. 新事务输入与恢复日志使用相同边界校验。先完整校验整份日志，再执行任何环境读写恢复。
3. 校验日志版本、事务 ID 格式、时间字段、列表及记录非空、重复键、字段一致性和字段存在性；区分缺失字段与合法 null，特别是注入值 null 表示清除变量。
4. 不允许 Restored 等缺省值掩盖结构损坏；对合法旧日志制定兼容策略，不能仅为严格校验而使正常历史恢复记录失效。说明哪些旧记录需要人工处理。
5. 非法日志保留并报告；拒绝新事务覆盖，不执行部分恢复。
6. 更新现有测试：TEST_VAR、MY_VAR 等自定义键改为允许变量名，但必须继续使用内存模拟环境。不要为了兼容测试放宽生产允许列表。

验收测试：PATH 等非允许键、重复键、null 记录、空键、未知版本、缺失必要字段、合法 null 清除值、合法历史记录；所有非法日志均须环境写入次数为零、日志未被覆盖。

## D. 跨会话锁失败必须停止用户环境操作【P1】

位置：EnvironmentTransaction.cs，DefaultTransactionLock。

缺陷：Global 锁创建失败后自动改用 Local 锁；不同实例可能持有不同作用域的锁，失去互斥保证。

要求：

- 禁止静默降级 Local 锁。无法取得正确 SID 或创建/打开约定的 Global 锁时明确失败，禁止操作用户环境。
- 对所需权限进行最小化处理，不扩大到任意用户可控制事务锁。
- 保留正确的 AbandonedMutexException 所有权处理。
- 将锁创建抽为最小可测试接缝，故障测试验证没有请求 Local 替代锁、没有环境或 WAL 写入。
- 模拟锁返回 true 不等于实测 Windows 跨会话互斥；报告中分开记录模拟控制流、原生互斥和跨会话实际验证。缺少条件的项目标记未验证。
